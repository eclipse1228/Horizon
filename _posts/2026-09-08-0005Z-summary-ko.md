## [LLM 기반 진화로 10개 원 패킹 기록 갱신, 비용 28달러](https://www.reddit.com/r/MachineLearning/comments/1w9xlyi/llmguided_program_evolution_improves_10_bestknown/) ⭐️ 8.0/10

Discovery Loop 시스템을 사용하여 LLM이 원 패킹 솔버에 대한 알고리즘 변경을 반복적으로 제안하여 Packomania 벤치마크에서 10개의 최고 알려진 솔루션(N=101-114)을 2.4~5.4% 개선했으며 총 비용은 27.72달러였습니다. 이는 LLM이 저비용 자동화된 최적화 알고리즘 발견을 주도하여 잘 알려진 벤치마크에서 수년간의 인간 노력을 능가할 수 있음을 보여줍니다. 이는 LLM이 직접 문제 해결자가 아닌 반복적 프로그램 진화 엔진으로 작동하는 새로운 패러다임을 제시합니다. Discovery Loop라고 불리는 이 시스템은 간단한 시드 솔버에서 시작하여 독립적인 검증기를 사용해 각 후보를 평가하고 개선된 것만 유지합니다. LLM 비용은 단 27.72달러였으며, 결과는 Packomania 벤치마크 관리자에 의해 승인되었습니다.

## [악성 크롤러가 git.kernel.org 서버를 압도하다](https://simonwillison.net/2026/Sep/7/creepy-crawlies/) ⭐️ 7.0/10

Kernel.org 유지보수자인 Konstantin Ryabitsev는 악성 크롤러가 Git 커밋을 HTML로 렌더링하는 데 소비하는 CPU 사이클이 git.kernel.org의 5개 지리적 분산 노드에서 발생하는 모든 합법적인 Git 작업의 합계를 초과하며, 14개 CPU 코어가 오로지 스크래퍼를 처리하는 데 사용되고 있다고 보고했습니다. 이는 동적 콘텐츠를 렌더링하는 모든 공개 웹 서비스, 특히 Git 저장소 브라우저와 Datasette 같은 도구에 심각한 지속 가능성 문제를 제기합니다. 해결되지 않으면 AI 훈련 크롤러의 증가하는 부담으로 인해 크롤링 가능한 웹 인터페이스가 경제적으로 유지 불가능해질 수 있습니다. 보고서에 따르면 git.kernel.org는 AI 크롤러로부터 하루 약 600만 건의 요청을 받으며, 서버는 각 요청에 대해 gitweb 또는 cgit을 사용하여 커밋 페이지를 HTML로 렌더링합니다. 유지보수자는 이러한 스크래핑 요청이 캐싱 이점을 전혀 제공하지 않는다고 지적했습니다. 각 스크래핑된 페이지는 일반적으로 크롤러에 의해 한 번만 방문되기 때문입니다.

rss · Simon Willison · 9월 7일 23:08

**배경**: Gitweb 및 cgit과 같은 Git 웹 인터페이스를 사용하면 전체 저장소를 클론하지 않고도 웹 브라우저를 통해 Git 저장소를 탐색할 수 있습니다. 이러한 인터페이스는 커밋 diff, 로그 및 파일 트리를 HTML 페이지로 동적으로 렌더링하며, 이는 계산 비용이 많이 듭니다. 악성 크롤러(주로 AI 회사가 훈련 데이터 수집을 위해 운영)는 캐싱 메커니즘을 우회하는 대량의 요청을 보내 서버가 각 고유 요청에 대해 페이지를 다시 생성하도록 강제합니다.

OpenAI의 수석 과학자 Jakub Pachocki는 더 강력한 AI 모델을 빠르게 훈련하는 가장 강력한 이유는 다른 AI가 초래하는 위험에 대한 방어 시스템을 구축하기 위해서라고 주장했습니다. 그는 인프라를 보호하고 악성 에이전트로부터 실시간 방어하기 위해 강력하고 정렬된 AI가 필요하다고 강조하면서, 이를 무분별한 가속의 핑계로 삼아서는 안 된다고 경고했습니다. OpenAI 최고 과학자의 이 발언은 AI 능력 개발과 안전 사이의 긴장을 직접적으로 다루며, 방어를 주요 동기로 제시하면서 무분별한 경쟁을 경고합니다. 이는 OpenAI의 전략적 우선순위를 시사하며 AI 정렬 및 실존적 위험에 대한 지속적인 논쟁에 무게를 더합니다. Pachocki의 주장은 OpenAI 블로그 게시물 'An Alien Mind'의 '확장 가능한 방어' 섹션에 나타납니다. 그는 방어적 AI를 OpenAI 배포 노력의 주요 초점으로 설명하며, 인프라 보안, 실시간 보호, 새로운 보호 조치 발명을 포함합니다.
