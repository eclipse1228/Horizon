## [Gemini 3.8 TTS 플레이그라운드: 2000개 이상의 음성 및 맞춤 음성 복제](https://simonwillison.net/2026/Sep/23/gemini-tts-playground/) ⭐️ 8.0/10

Google은 gemini-3.8-flash-tts와 gemini-3.8-flash-lite-tts라는 두 가지 새로운 Gemini 3.8 텍스트 음성 변환 모델을 출시했습니다. 이 모델은 2,000개 이상의 음성 라이브러리와 30초 오디오 샘플로 맞춤 음성을 복제할 수 있는 기능을 제공합니다. Simon Willison은 GPT-6 Astra를 사용하여 사용자가 자신의 API 키를 가져와 다양한 음성과 전달 스타일로 다중 화자 대화를 구성할 수 있는 플레이그라운드 인터페이스를 구축했습니다. 이번 출시는 방대한 음성 라이브러리와 손쉬운 맞춤 음성 복제를 통해 고품질의 표현력 있는 텍스트 음성 변환에 대한 접근성을 크게 확장하여 개발자, 콘텐츠 제작자 및 접근성 애플리케이션의 진입 장벽을 낮춥니다. 함께 제공되는 플레이그라운드 도구는 API를 실험할 수 있는 실용적이고 설정이 필요 없는 방법을 제공하여 팟캐스트나 오디오북과 같은 다중 화자 오디오 콘텐츠의 프로토타입 제작을 더 쉽게 만듭니다. 플레이그라운드는 각 캐릭터가 고유한 음성과 전달 스타일 지침을 가질 수 있는 다중 화자 대화를 지원하며, 모든 구성 설정은 공유를 위해 URL에 저장됩니다. 전체 flash 모델로 1분 18초의 오디오를 생성하는 데 단 2.74센트가 소요되었고 약 20초가 걸려 모델의 속도와 비용 효율성을 보여주었습니다.

## [이탈리아 의회, SMR을 통한 원자력 재개 추진](https://apnews.com/article/italy-nuclear-chernobyl-4891b6b7c7791ae84db6b0bf0f7cf567) ⭐️ 7.0/10

이탈리아 의회는 소형 모듈 원자로(SMR)와 첨단 기술에 초점을 맞춰 원자력 발전 재개를 위한 규제 프레임워크를 마련하는 결의안을 통과시켰습니다. 이 첫 단계는 원자로 건설을 승인하는 것이 아니라 향후 제안을 위한 법적 기반을 마련합니다. 이는 1987년 체르노빌 사고 이후 원자력 발전을 금지해 온 이탈리아의 주요 정책 반전을 의미합니다. 성공한다면 국가의 에너지 믹스를 재편하고 탈탄소화를 지원할 수 있지만, 경제성 및 투자 장벽은 여전히 큽니다. 이 법안은 규제 기반만 마련할 뿐, 아직 원자로 건설은 승인되지 않았습니다. 정부는 특히 모듈당 최대 300MW를 생산하며 공장 제작 및 수동적 안전 기능을 갖춘 SMR을 목표로 하고 있습니다.

## [Windows 스크롤바 단축키의 역사적 개요](https://devblogs.microsoft.com/oldnewthing/20260922-00/?p=112719/) ⭐️ 5.0/10

최신 블로그 게시물에서 Raymond Chen은 Windows 스크롤바 단축키의 역사적 개요를 제공하며, 초기 Win32 구현부터 현대 사용자 정의 스크롤바의 불일치까지의 진화를 추적합니다. 이 글은 프레임워크가 기본 스크롤바를 다르게 동작하거나 기능이 부족한 사용자 정의 스크롤바로 대체함에 따라 Windows 애플리케이션에서 일관된 사용자 경험이 점차 사라지고 있음을 조명합니다. 이 역사를 이해하는 것은 일관된 UI 동작의 중요성을 깨닫는 데 도움이 됩니다. 이 게시물은 거터를 클릭하여 해당 위치로 스크롤하는 것(Ctrl을 누르면 Page Up/Down)과 같은 고전적인 단축키를 다루며, Qt 및 GTK와 같은 많은 현대 프레임워크가 이를 일관성 없이 구현한다고 지적합니다. Raymond Chen은 또한 Win32 스크롤바를 사용하는 애플리케이션이 거의 없어 사용자가 한때 의존했던 예측 가능한 동작이 사라졌다고 한탄합니다.

hackernews · tybulewicz · 9월 23일 18:02 · [토론](https://news.ycombinator.com/item?id=49820065)

**배경**: Win32 스크롤바는 Windows API를 사용하는 모든 애플리케이션에서 일관된 동작을 제공하는 네이티브 Windows 컨트롤입니다. 역사적으로 스크롤바 거터를 클릭하면 해당 위치로 스크롤되고 화살표를 클릭하면 한 줄씩 스크롤되었습니다. 현대 UI 프레임워크는 종종 이러한 기능이 부족하거나 다르게 동작하는 사용자 정의 스크롤바로 이를 대체하여 오랫동안 확립된 사용자 기대를 깨뜨립니다.

**토론**: 댓글은 현대 사용자 정의 스크롤바에 대한 불만을 표출합니다: bartread는 일관된 UX의 상실을 한탄하고, mrob는 '여기로 스크롤'이 기본 클릭 동작이어야 하며 GTK는 제대로 하지만 Qt는 그렇지 않다고 지적하며, butz는 얇거나 숨겨진 스크롤바를 우려하고, chrismorgan은 Linux/GTK 전반의 다양한 불일치 동작을 설명합니다. layer8는 Raymond Chen이 UI 불일치에 대해 더 많은 불만을 토로하기를 요청합니다.

## [인터랙티브 도구로 CSS 섀도우 루트를 실시간 예제와 함께 설명](https://simonwillison.net/2026/Sep/23/shadow-roots/) ⭐️ 5.0/10

Simon Willison이 간단한 프롬프트로 AI 모델(Fable 5.1 Medium)을 사용해 생성된 라이브 예제로 CSS 섀도우 루트를 설명하는 인터랙티브 도구를 공개했습니다. 섀도우 루트는 Shadow DOM 사양의 핵심 부분으로, 웹 컴포넌트에서 스타일과 마크업 캡슐화를 가능하게 합니다. 이 도구는 이 강력하지만 종종 오해받는 웹 플랫폼 기능을 처음 접하는 개발자들의 학습 곡선을 낮춰줍니다. 이 도구는 Fable 5.1 Medium에 "Build an artifact to explain shadow roots in CSS with interactive examples"라는 프롬프트를 입력하여 생성되었습니다. tools.simonwillison.net/shadow-roots에서 호스팅되며 CSS, Shadow DOM, Web Components, 인터랙티브 튜토리얼 태그가 붙어 있습니다.

rss · Simon Willison · 9월 23일 16:37

**배경**: Shadow DOM은 개발자가 요소에 숨겨진 DOM 트리(섀도우 트리)를 연결하여 구조와 스타일을 캡슐화함으로써 페이지의 다른 부분과 간섭하지 않도록 하는 브라우저 기능입니다. 이러한 숨겨진 트리의 루트를 섀도우 루트라고 합니다. 이 캡슐화는 한 컴포넌트의 CSS 규칙이나 JavaScript가 다른 컴포넌트에 의도치 않게 영향을 미치는 일반적인 문제를 해결하며, Custom Elements 및 HTML 템플릿과 함께 Web Components의 핵심 기술입니다.
