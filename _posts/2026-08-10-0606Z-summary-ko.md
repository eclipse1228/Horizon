## [GitHub Models 서비스 종료, Actions 내 LLM 워크플로에 영향](https://simonwillison.net/2026/Aug/9/github-models-is-now-retired/#atom-everything) ⭐️ 7.0/10

GitHub Models(통합 LLM 추론 API)가 2026년 7월 30일부로 완전히 종료되었습니다. GitHub Actions에서 이를 사용하던 개발자들은 이제 오류를 겪으며 대체 제공업체로 마이그레이션해야 합니다. 이번 종료로 CI/CD 파이프라인, 특히 GitHub Actions에 LLM 호출을 통합하는 편리하고 무료인 옵션이 사라졌습니다. 내장 GitHub API 키를 인증에 사용하던 개발자들은 이제 자체 API 키와 비용을 관리해야 하므로 복잡성과 비용이 증가할 수 있습니다. GitHub는 종료 사유를 밝히지 않았지만, 코딩 에이전트 패턴에 대한 토큰 보조금의 높은 비용이 원인으로 추정됩니다. 종료 전에 예정된 브라운아웃이 있었으며, 현재 playground, 모델 카탈로그, 추론 API를 포함한 모든 서비스를 완전히 사용할 수 없습니다.

rss · Simon Willison · 8월 9일 22:48

**배경**: GitHub Models는 OpenAI, DeepSeek, Meta 등 여러 제공업체의 다양한 LLM에 통합 API로 접근할 수 있는 플랫폼으로, GitHub 생태계 내에서 직접 작동했습니다. 주요 장점은 GitHub Actions 워크플로가 기존 GitHub API 키를 사용하여 인증할 수 있어 별도 결제나 키 관리가 필요 없었다는 점입니다. GitHub Next가 추진한 Continuous AI 개념은 LLM을 저장소 내에서 CI 작업과 유사하게 추론이 필요한 작업을 수행하는 백그라운드 에이전트로 사용하는 것을 구상했습니다. GitHub Models는 이러한 워크플로의 핵심 동력이었습니다.

## [SQLite 압축 텍스트 기록 프로토타입](https://simonwillison.net/2026/Aug/9/sqlite-text-history-prototype/#atom-everything) ⭐️ 6.0/10

Simon Willison이 SQLite에 개정 기록을 저장하는 방법을 프로토타입으로 구현했습니다. 이전 버전의 전체 텍스트를 zstd 압축 JSON 배열로 압축하여 1,000회의 시뮬레이션 편집에서 254배의 압축률을 달성했습니다. 이 접근 방식은 SQLite 내에서 직접 문서 개정 기록을 공간 효율적으로 저장할 수 있는 실용적인 방법을 제공하며, 추가 저장 오버헤드 없이 버전 관리가 필요한 노트 앱이나 콘텐츠 관리 시스템에 유용할 수 있습니다. 프로토타입은 기록을 여러 행으로 분할하며, 각 행은 최대 128개의 개정 또는 3MB의 압축되지 않은 JSON으로 제한되어 매 편집마다 전체 배열을 압축 해제하고 재압축하는 것을 방지합니다. 이 아이디어는 OpenAI의 GPT-Live 음성 모드 및 GPT-5.6 Sol Pro와의 협업을 통해 개발되었습니다.

rss · Simon Willison · 8월 9일 22:05

**배경**: SQLite는 모바일 앱 및 데스크톱 소프트웨어에서 널리 사용되는 경량 임베디드 관계형 데이터베이스입니다. 전통적으로 개정 기록을 저장하려면 각 버전당 하나의 행을 가진 별도의 테이블(문서 크기에 따라 선형적으로 증가)이나 외부 버전 관리 시스템이 필요합니다. zlib 및 zstd와 같은 압축 알고리즘은 반복되는 텍스트의 중복성을 활용하여 저장 공간을 대폭 줄여 데이터베이스 내 버전 관리를 더 실현 가능하게 만듭니다.
