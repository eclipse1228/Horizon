## [LLM과 샌드박싱으로 안전한 사용자 확장 소프트웨어 구현](https://simonwillison.net/2026/Aug/19/jeremy-morrell/) ⭐️ 8.0/10

Jeremy Morrell은 LLM과 WebAssembly 같은 현대적 샌드박싱 기술을 결합하면 사용자가 AI 생성 코드로 안전하게 애플리케이션을 확장할 수 있는 새로운 소프트웨어 패러다임이 가능하다고 제안합니다. 이는 소프트웨어 확장성의 비용과 보안 위험을 낮추어 비개발자 사용자도 애플리케이션을 강력하게 맞춤 설정할 수 있게 하며, 소프트웨어 설계 및 배포 방식을 변화시킬 잠재력이 있습니다. LLM은 확장 코드 작성 비용을 획기적으로 낮추고, WebAssembly 같은 샌드박스 환경은 장애 격리 기술로 강력한 격리를 제공하여 신뢰할 수 없는 AI 생성 코드를 안전하게 실행할 수 있게 합니다.

## [AI 코딩 에이전트에게 코드 라인이 유효한 지표가 될 수 있다](https://simonwillison.net/2026/Aug/19/conceptual-integrity-and-counting-lines-of-code/) ⭐️ 7.0/10

Simon Willison은 전통적인 소프트웨어 공학 지혜와 달리 AI 코딩 에이전트를 사용할 때 코드 라인 측정이 생산성의 유효한 지표가 될 수 있다고 주장합니다. 인간은 하루에 50~200줄의 디버깅된 코드를 생산하는 반면 에이전트는 수천 줄을 생성할 수 있지만 인지 용량이 새로운 병목 현상이 된다고 강조합니다. 이는 코드 라인이 결코 의미 있는 지표가 아니라는 오랜 소프트웨어 공학 독단에 도전합니다. AI 코딩 에이전트가 더 강력해짐에 따라 인지 부하와 개념적 무결성 같은 새로운 생산성 한계를 이해하는 것이 팀 설계와 도구 채택에 중요합니다. Willison은 에이전트를 사용하면 코드를 훨씬 더 빠르게 생산할 수 있지만 코드를 관리하는 인지 용량이 이제 제한 요소가 된다고 자신의 경험을 인용합니다. 그는 에이전트가 '윈체스터 미스터리 하우스' 문제를 일으킬 수 있다고 경고하는데, 이는 싸게 추가된 기능들로 인해 소프트웨어가 일관성을 잃는 현상입니다.

## [회전(Turn)이 라디안보다 낫다 (2022)](https://www.computerenhance.com/p/turns-are-better-than-radians) ⭐️ 6.0/10

2022년의 한 의견 기사는 프로그래밍에서 각도를 표현할 때 라디안 대신 회전(한 바퀴)을 사용하면 부동소수점 반올림 오류를 피하고 사분원 회전 같은 일반적인 각도에 대한 추론을 단순화할 수 있다고 주장합니다. 이 논쟁은 삼각함수를 다루는 프로그래머에게 중요합니다. 수치 정밀도와 코드 명확성에 영향을 미칠 수 있지만, 미적분학 및 부동소수점 라이브러리 성능과의 균형이 중요하게 작용합니다. 기사는 회전을 사용할 때 전체 원의 일반적인 분수(예: 1/4, 1/8)가 이진 부동소수점에서 정확히 표현될 수 있지만, 라디안은 이러한 각도에 대해 반올림 오류를 자주 발생시킨다고 지적합니다.

hackernews · mayoff · 8월 20일 01:29 · [토론](https://news.ycombinator.com/item?id=49369408)

**배경**: 라디안은 수학에서 각도의 표준 단위로, 미적분을 단순화하여 삼각함수의 도함수가 인수 자체에 비례하게 합니다. 회전(또는 바퀴)은 종종 공학 및 항법에서 사용되며, 여기서 한 바퀴는 1회전입니다. 기사는 프로그래밍에서 회전이 일반적인 각도의 정확한 표현과 더 직관적인 추론을 제공한다고 주장하지만, 비판자들은 d/dx sin(2πx) = 2π cos(2πx)와 같은 도함수에 추가 요소가 도입되고 회전을 사용하면 부동소수점 라이브러리 구현이 더 복잡해진다고 지적합니다.

## [Simon Willison, smolvm을 신뢰할 수 없는 코드 샌드박스로 테스트하다](https://simonwillison.net/2026/Aug/19/smolmachines-untrusted-sandbox/) ⭐️ 6.0/10

Simon Willison은 smolmachines/smolvm을 신뢰할 수 없는 Python 및 JavaScript 코드를 실행하기 위한 보안 샌드박스로 실험했습니다. 그는 Claude Code for web을 사용하여 테스트를 조정했지만, Claude Code 환경이 중첩 가상화를 지원하지 않아 GitHub Actions 워크플로를 사용해야 했습니다. 이 탐구는 리소스 제한, 네트워크 격리 및 파일 시스템 접근 제한 하에서 사용자가 제공한 데이터 변환 코드를 안전하게 실행하는 실용적인 접근 방식을 보여줍니다. 이러한 샌드박스는 보안을 손상시키지 않고 사용자의 신뢰할 수 없는 코드를 실행해야 하는 플랫폼에 매우 중요합니다. smolvm 엔진은 상태 유지 가상 머신을 단일 .smolmachine 파일로 패키징하며, Node.js 네이티브 애드온을 통해 프로세스 내에서 연결할 수 있습니다. Simon의 테스트는 smolvm 1.8.3을 사용하여 신뢰할 수 없는 Python 및 JavaScript를 실행했으며, GitHub Actions 러너에는 /dev/kvm이 있어 하드웨어 격리 VM을 사용할 수 있었습니다.

rss · Simon Willison · 8월 19일 23:16

**배경**: 신뢰할 수 없는 코드를 샌드박싱하는 것은 사용자가 사용자 정의 스크립트나 변환을 실행할 수 있도록 허용하는 소프트웨어 플랫폼에서 일반적인 과제입니다. 전통적인 접근 방식은 공유 커널을 사용하는 컨테이너(예: Docker)를 사용하지만, 보안 취약점이 있을 수 있습니다. Smolvm은 하드웨어 격리된 경량 가상 머신을 사용하는 대안을 제공하여 더 강력한 보안 보장을 제공합니다. Claude Code for web은 클라우드 환경에서 작업을 실행하는 원격 코딩 에이전트이지만, VM 내에서 VM을 실행하는 데 필요한 중첩 가상화를 위해 /dev/kvm이 없을 수 있습니다.
