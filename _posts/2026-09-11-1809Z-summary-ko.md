## [Python 3.15, re.match()를 소프트 폐기하고 re.prefixmatch()를 권장](https://simonwillison.net/2026/Sep/11/soft-deprecating-re-match/) ⭐️ 8.0/10

2026년 10월 출시 예정인 Python 3.15에서는 re.match()의 정확한 동의어로 re.prefixmatch()를 도입하고, re.match()를 소프트 폐기하여 더 명확한 이름을 사용하도록 권장합니다. 소프트 폐기는 re.match()가 제거되지는 않지만 새 코드에서는 re.prefixmatch()를 사용해야 함을 의미합니다. 이 변경은 re.match()의 앵커링 동작(시작 부분에만 고정되고 끝에는 고정되지 않음)에 대한 오랜 혼란을 줄여 Python의 정규 표현식 API를 더 직관적으로 만듭니다. 이는 정규 표현식을 사용하는 수백만 Python 개발자에게 영향을 미칩니다. re.prefixmatch()는 Python 3.15에서 re.match()의 정확한 동의어이며, 동작 변경은 없습니다. 소프트 폐기는 PEP 387의 정책을 따르므로 제거 일정이 없으며 기존 코드는 계속 작동합니다.

rss · Simon Willison · 9월 11일 14:47

**배경**: Python의 re 모듈은 여러 정규 표현식 함수를 제공합니다: re.match()는 문자열 시작 부분에서만 일치를 확인하고, re.search()는 어디서든 확인합니다. 많은 개발자가 re.match()가 전체 문자열과 일치할 것이라고 잘못 생각하여 버그가 발생합니다. 소프트 폐기는 PEP 387에 정의된 개념으로, 새 코드에서는 API 사용을 권장하지 않지만 제거 일정은 없어 기존 코드를 깨뜨리지 않고 점진적으로 마이그레이션할 수 있습니다.

## [Wrapture: 테스트와 관측 가능성을 통합하는 새로운 파이썬 라이브러리](https://simonwillison.net/2026/Sep/11/wrapture/) ⭐️ 8.0/10

Graham Dumpleton이 2026년 8월 31일 테스트와 관측 가능성을 하나로 통합하는 새로운 파이썬 몽키 패칭 라이브러리 wrapture를 출시했다. 이후 그는 단위 테스트, 호출 기록, 실시간 트레이싱, TOML 기반 무코드 트레이싱, OpenTelemetry 내보내기 등을 다루는 튜토리얼을 거의 매일 공개하고 있다. Wrapture는 안전한 몽키 패칭 메커니즘 하나로 테스트와 관측 가능성을 모두 해결하기 때문에 파이썬 개발자에게 없어서는 안 될 도구가 될 수 있다. 코드 없는 TOML 설정과 주요 프레임워크용 사전 계측(instrumentation) 덕분에 실제 애플리케이션 트레이싱 진입 장벽이 크게 낮아진다. Wrapture는 아직 알파 소프트웨어이지만 이미 충분히 사용 가능하며, Graham Dumpleton이 이전에 만든 wrapt 프로젝트의 안전한 몽키 패칭 메커니즘 위에 구축되었다. 함께 제공되는 wrapture-instrumentation 패키지는 Flask, Django, FastAPI, SQLAlchemy, httpx, requests 등을 지원하며, JupyterLab 기반 대화형 워크숍도 마련되어 있다.

rss · Simon Willison · 9월 11일 13:51

**배경**: 몽키 패칭(monkey patching)은 소스 코드를 바꾸는 대신 런타임에 코드를 동적으로 수정해 메모리상의 메서드·클래스·함수를 교체하거나 추가하는 기법이다. 주로 서드파티 라이브러리를 고치거나 확장하는 데 쓰이며, 파이썬에서는 unittest.mock 같은 도구의 기반이 된다. ## [보리스 체르니: AI 코드는 사람이 작성한 코드보다 더 높은 기준을 충족해야 한다](https://simonwillison.net/2026/Sep/11/boris-cherny/) ⭐️ 7.0/10

Cherny는 이러한 조치 없이는 AI가 생성한 코드가 시간이 지남에 따라 유지보수하기 어려운 지저분한 코드베이스로 이어질 수 있다고 경고했습니다.
